## 1. โจทย์

- ทำ hero หน้าแรกอีกแบบ เป็น **การเลื่อนเล่าเรื่องเต็มจอ** แบบสุดทาง
- มี **ปุ่มสลับ** ระหว่าง "แบบเลื่อน" กับ "แบบเดิม" (hero วน A → B ที่ทำไว้) ให้กดเทียบกันได้ในหน้าเดียว
- ต้องคิดจากธุรกิจทีมดี ไม่ใช่เอาท่าเลื่อนสวยๆ มาแปะ

## 2. ทำไมการเลื่อนเล่าเรื่องถึงเหมาะกับทีมดี (และตรงไหนไม่เหมาะ)

**เหมาะ เพราะของที่เราขายคือ "ขั้นตอน" ไม่ใช่สินค้าชิ้นเดียว**
ลูกค้าไม่ได้ซื้อเสื้อสำเร็จรูป เขาซื้อการเดินทางจาก "ยังไม่มีอะไรในมือ" ไปถึง "ทั้งทีมได้ใส่" ซึ่งเป็นเรื่องที่มีลำดับ การเลื่อนคือการเล่าลำดับที่คนคุมเองได้ ตรงกับ **ช่วยคิด → ช่วยจัดการ → ช่วยจบงาน** และ 3WIN (คนสั่งมั่นใจ · คนใส่ภูมิใจ · คนเห็นจดจำ)

**ไม่เหมาะ ถ้าทำผิด 4 แบบ**
1. คนจากโฆษณาหรือลิงก์ทีมขายอยากทักไลน์เลย แต่ต้องเลื่อน 5 จอกว่าจะเจอปุ่ม → แก้ด้วยปุ่มข้ามเรื่อง + แถบล่างมือถือ (ทักไลน์ · โทร · ดูแบบ) ที่มีอยู่แล้วต้องอยู่ตลอด
2. ฝ่ายจัดซื้อและราชการอยากเห็นข้อเท็จจริงเร็ว ไม่ได้อยากดูหนัง → ทุกบทต้องมีประโยคข้อเท็จจริงที่อ่านจบได้ในบทเดียว และมีลิงก์ "ข้ามไปเนื้อหา"
3. ลูกค้าไทยจำนวนมากเปิดลิงก์จาก **LINE ซึ่งเปิดในเบราว์เซอร์ในแอป** ท่าตรึงจอ (pin) กับการเลื่อนแบบผูกเฟรมมักกระตุกในนั้น → ต้องทดสอบในเบราว์เซอร์ LINE จริงก่อนเปิดใช้ และมีโหมดเบาสำรอง
4. ถ้าเนื้อหาอยู่ในภาพหรือ canvas Google จะอ่านไม่ได้ → ตัวหนังสือทุกบทเป็น HTML จริง เรียงตามลำดับเดียวกับที่เห็น

## 3. เนื้อเรื่อง · 6 บท (ร่างสตอรี่บอร์ด)

ฉากตรึงอยู่กับที่ (sticky) ราว 5–6 จอ เลื่อนลงแล้วภาพเปลี่ยนตามระยะที่เลื่อน เลื่อนขึ้นก็ย้อนกลับได้

| บท | ระยะเลื่อน | ภาพ | ตัวหนังสือ (HTML จริง) | ใช้ของอะไร |
|---|---|---|---|---|
| **0 · เปิด** | 0–60% จอ | เสื้อเปล่าสีขาวตัวใหญ่กลางจอ พื้นผ้าดำ | **เสื้อทีมที่ทุกคนภูมิใจจะใส่** · ออกแบบและผลิตเสื้อทีม ให้บริษัท โรงเรียน ทีมกีฬา และงานกิจกรรม | ลายเส้นเสื้อ SVG |
| **1 · ช่วยคิด · โจทย์** | 60–160% | ป้ายโจทย์ลอยเข้ามาเกาะเสื้อทีละใบ: ใครใส่ · ใส่ตอนไหน · กี่ตัว · อยากให้คนเห็นแล้วรู้สึกยังไง | ไม่มีแบบก็เริ่มได้ บอกแค่สี่เรื่องนี้ | ข้อความเท่านั้น |
| **2 · ช่วยคิด · ออกแบบ** | 160–280% | เสื้อค่อยๆ ได้สี → ริ้วเฉียงตาม CI → โลโก้ → ชื่อ-เบอร์ แล้วกลับด้านหน้า-หลัง ติดป้ายรหัส TD | ดีไซเนอร์ขึ้นแบบให้ดูก่อน แก้จนพอใจ [ยืนยันเงื่อนไขการแก้] | ลายเส้นเสื้อ SVG ที่มีชั้นสี ลาย โลโก้ แยกกัน |
| **3 · ผนังแบบเสื้อ** | 280–360% | กล้องถอยออก เสื้อตัวนั้นกลายเป็นช่องหนึ่งบนผนังแบบจริง 33 แบบที่วิ่งสวนกัน | 33 แบบที่ทำให้ทีมจริง ทุกแบบมีรหัส เซฟไปคุยต่อได้ · ปุ่มดูแบบเสื้อ | แบบเสื้อ 33 แบบ (มีแล้ว) = ฉาก B เดิม |
| **4 · ช่วยจัดการ** | 360–440% | ภาพโรงงานจริง 3 จังหวะ: เทียบผ้า → พิมพ์/ปัก → ตรวจงานก่อนแพ็ก | ยืนยันสเปกเป็นลายลักษณ์อักษร · ผลิตและถ่ายรูปงานจริงให้ดูก่อนส่ง [ยืนยันขั้นตอน] | **ต้องได้รูปโรงงานจริง** (มี 3 รูปเก่าใน /img/hero) |
| **5 · ช่วยจบงาน** | 440–540% | แบบเสื้อหนึ่งตัว → รูปทีมที่ใส่ตัวนั้นจริง แล้วแตกเป็นรูปทีมจริงหลายประเภทงาน กดไปหน้าการใช้งานได้ | ทีมนี้ใส่จริงในวันงาน · ตัวเลขหลักฐาน 3 ช่อง | **คู่แบบ + รูปทีมของงานเดียวกัน** (= ฉาก A เดิม) · ตัวเลขที่ยืนยันแล้ว |
| **6 · ชวนคุย** | ปลายทาง ตรึงจบ | เสื้อเปล่ากลับมา พร้อมช่องพิมพ์ชื่อทีม (ต่อยอดจากร่าง C) | ทีมของคุณคือทีมต่อไป · ทักไลน์ · ดูแบบเสื้อ · ปรึกษาทีมดี | ลายเส้นเสื้อ SVG |

จากนั้นหน้าเลื่อนต่อเป็นส่วน 2–7 ของหน้าแรกตามเดิม (หาเสื้อที่เหมาะ · ผลงาน · แบบที่คัดมา · FAQ · ชวนคุย)

**ทุกบทมี:** ชื่อบทเล็กๆ (01 ช่วยคิด · 02 ช่วยจัดการ · 03 ช่วยจบงาน) · แถบความคืบหน้าด้านข้าง · ปุ่ม "ข้ามเรื่อง ไปดูแบบเสื้อ"

## 4. ปุ่มสลับ "แบบเลื่อน ↔ แบบเดิม"

- ปุ่มเล็กมุมบนของ hero: **ดูแบบเดิม** / **ดูแบบเลื่อน** (กดแล้วสลับทันที ไม่โหลดหน้าใหม่)
- จำค่าที่เลือกไว้ในเครื่อง (localStorage) และรับ `?hero=scroll` / `?hero=classic` ในลิงก์ ให้ส่งลิงก์ให้พี่ทัชเปิดเทียบได้ตรงแบบ
- ทั้งสองแบบอยู่ใน HTML หน้าเดียว แสดงทีละแบบ แบบที่ซ่อนไม่โหลดรูปและไม่เดินภาพเคลื่อนไหว
- **ช่วงต้นแบบ** ปุ่มนี้มีไว้เทียบภายใน **ก่อนขึ้นจริง** ต้องเลือกแบบเดียว หรือเปลี่ยนเป็นการทดสอบ A/B ที่วัดผลจริง (ข้อ 8) แล้วถอดปุ่มออก

## 5. วิธีทำ (เทคนิค)

| เรื่อง | ทางที่เลือก | เหตุผล |
|---|---|---|
| ผูกภาพกับการเลื่อน | **CSS scroll-driven animations** (`animation-timeline: view()` / `scroll()`) | เบราว์เซอร์คำนวณนอกเธรดหลัก ลื่นกว่าใช้ JS ฟังการเลื่อน · ไม่ต้องเพิ่มไลบรารี |
| เบราว์เซอร์ที่ยังไม่รองรับ | `@supports (animation-timeline: view())` ไม่ผ่าน → แสดงเป็นบทนิ่งเรียงลงมา อ่านครบทุกบท | ยังได้เนื้อหาครบ ไม่พัง |
| ตรึงจอ | `position: sticky` ในกล่องสูง ~600vh | ไม่แย่งการเลื่อนของผู้ใช้ (ไม่ทำ scroll-jacking) |
| ภาพเสื้อที่เปลี่ยนตามบท | SVG ชั้นเดียว แยกชั้นสี · ลาย · โลโก้ · ชื่อเบอร์ ขยับแค่ `opacity` / `transform` | คมทุกขนาดจอ ไฟล์เล็ก |
| ผนังแบบเสื้อ | 6 คอลัมน์วิ่งสวนกัน ขยับทั้งคอลัมน์ | ใช้บทเรียนจากแบบเดิม: 66 ช่องขยับแยก = เฟรมค้าง 50–333ms ตอนขึ้นครั้งแรก |
| ทางเลือกถ้า CSS ล้วนไม่พอ | GSAP + ScrollTrigger (ฟรีแล้ว) | ใช้เมื่อเจอข้อจำกัดจริงเท่านั้น เพิ่ม dependency ราว 100KB (ก่อนบีบอัด) ต้องถามก่อน |
| ลดการเคลื่อนไหว | `prefers-reduced-motion` → บทนิ่งเรียงลงมา ไม่มีตรึงจอ | ข้อบังคับ a11y |

**งบความลื่น** ทุกบทต้องผ่าน: เฟรมเกิน 20ms ไม่เกิน 1% ของเฟรมทั้งหมด วัดด้วยสคริปต์ Chrome headless ที่ใช้กับแบบเดิม (`framebench`) ทั้งตอนเปิดครั้งแรก (cold) และครั้งที่สอง ที่ 1280 × 2x และ 375 × 3x

| ของ | ใช้ในบท | ตอนนี้ |
|---|---|---|
| **ลายเส้นเสื้อเวกเตอร์ที่แยกชั้นได้** (ตัวเสื้อ · ปก · แขน · ลาย · โลโก้) ด้านหน้า-หลัง | 0, 2, 6 | ไม่มี · ร่างเองได้แต่จะดูเป็นของเล่น (เห็นแล้วในร่าง C) · **อาร์ตทำได้ดีกว่าผม** |

| ตัวเลขหลักฐานที่ยืนยันแล้ว | 5 | รอพี่ทัช |

## 8. จะรู้ได้ยังไงว่าแบบไหนดีกว่า

ตอนนี้เทียบได้แค่ด้วยตา หลังขึ้นจริงควรวัด (ต้องต่อระบบวัดผลก่อน · เรื่องแยก):
- สัดส่วนคนที่กด **ทักไลน์ / ดูแบบเสื้อ / กรอกฟอร์ม** จาก hero
- คนเลื่อนผ่านบทไหนแล้วออก (บทไหนน่าเบื่อ)
- เวลาจนถึงการกดครั้งแรก
- แยกมือถือ / คอม และแยกคนที่มาจาก LINE

## 9. ต้องเคาะก่อนเริ่ม

1. **เนื้อเรื่อง 6 บทนี้ใช่ไหม** หรืออยากตัด/เพิ่มบทไหน (เช่น ตัดบทโรงงานถ้ายังไม่มีรูป)
2. **ลายเส้นเสื้อ** อาร์ตทำเอง หรือให้ผมร่างไปก่อนแล้วค่อยเปลี่ยน
3. **ความยาว** 5–6 จอ หรือสั้นกว่านี้ (สั้น = คนเห็นปุ่มเร็ว · ยาว = เล่าได้ครบ)
4. **แบบเดิมยังต้องแก้อาการสะดุดต่อไหม** — แนวแก้มีแล้ว (ผนังคอลัมน์ + ริ้วส้มกวาดตอนเปลี่ยนฉาก + วาดผนังเก็บไว้ก่อน) ทำพร้อม S3 ได้เลย

## 10. ภาคผนวก · บทเรียนจากแบบเดิม (วัดจริง 2 ต.ค. 2026)

- รอบที่สองเป็นต้นไปลื่น 60fps · สะดุดเฉพาะ **ครั้งแรกที่ผนังขึ้น** 50–333ms ขึ้นกับว่าเบราว์เซอร์ "เย็น" แค่ไหน
- ปิดการขยับรายช่อง 66 ช่อง → เหลือ 33ms → ต้นเหตุหลักคือจำนวนชั้นที่ขยับแยกกันและการวาดครั้งแรก
- การ์ดลงพลาดเป้า 37–45px เพราะรวม translate ไว้ใน transform ขณะ rotate แยก · แก้แล้วด้วย `flightFrames` (มีเทส)
- รูปคู่ถัดไปต้องโหลดและถอดรหัสก่อนถึงคิว ไม่งั้นรูปเก่าค้างแล้วสลับกลางทาง
