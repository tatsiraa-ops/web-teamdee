4 เรื่องที่ผมตัดสินใจแทนไม่ได้

เรียงจากเรื่องที่กระทบวันขึ้นจริงมากที่สุด ทุกข้อมีทางที่ผมเสนอไว้แล้ว ตอบแค่ "เอาตามที่เสนอ" ก็เริ่มได้

1 · ขวางวันขึ้นจริง

สิทธิ์เข้า WordPress เว็บจริง + Search Console

บทความเดิม 12 เรื่อง หมวดบทความ 3 หมวด และหน้าเดิมอย่าง /services/ /pdpa/ /calculations/ อยู่ใน CMS เว็บจริงที่สร้างด้วย Elementor Pro ต้องเห็นของจริงบน staging ว่าแสดงผลกับธีมใหม่ได้ ไม่งั้นเปลี่ยนธีมวันที่ 9 แล้วหน้าพวกนี้อาจพัง

เสนอ: ขอพี่ทัชเชิญผมเป็นผู้ใช้ WordPress + Search Console แบบมีสิทธิ์เท่าที่ต้องใช้ ภายใน 30 ต.ค. (ไม่ส่งรหัสผ่านในแชท) แล้วทำ staging จากสำเนาเว็บจริง
2 · ฟอร์มขอราคา

ข้อมูลในฟอร์มจะส่งไปที่ไหน

ตอนนี้ฟอร์มยังไม่ได้ส่งข้อมูลไปที่ไหน แค่คัดลอกข้อความแล้วพาไป LINE ซึ่ง v22 สั่งให้เชื่อมระบบรับข้อมูลจริง

เสนอ: ใช้ฟอร์มของ WordPress ส่งเข้าอีเมลทีมขาย และยังพาไป LINE ต่อเหมือนเดิม ไม่ต้องใช้ระบบนอก (ถ้าจะเก็บลง Supabase ต้องคุยแยก ตามกฎข้อ 3) · ต้องได้อีเมลที่รับฟอร์มกับชื่อคนตอบลูกค้า
3 · ชื่อหน้า

title หน้า /corporate/ กับ /size-chart/

2 หน้านี้ผมเคยปรับตามที่อาร์ตสั่ง (เน้น "ยูนิฟอร์ม" และใส่ทั้ง "ไซซ์" กับ "ไซส์") แต่ v22 กำหนด title ไว้อีกแบบ

เสนอ: title ใช้ตาม v22 ส่วน "ยูนิฟอร์ม" และ "ไซส์" ย้ายไปอยู่ใน description กับหัวข้อรอง Google ยังเห็นคำนี้ และไม่ขัด v22
4 · คลังแบบเสื้อ

ใช้รูปจากหน้าแกลเลอรีเว็บจริงได้ไหม

หน้าแกลเลอรีเดิมบนเว็บจริงมี 55–78 รูปต่อหน้า คลังของเรามี 33 แบบ ถ้าเอาขึ้นไปแทนตอนนี้ หน้าที่ติดอันดับอยู่จะเหลือรูปไม่กี่รูป

เสนอ: ดึงรูปจากเว็บจริงเข้าคลังก่อน (เป็นรูปของทีมดีเอง) แล้วให้ทีมดีไซน์ยืนยันรหัสแบบกับกลุ่มลูกค้าทีหลัง จะทำหน้า /design-[รหัส]/ ก็ต่อเมื่อได้รหัสจริงแล้วเท่านั้น
ตรวจรอบนี้เจออะไร

ปัญหาที่ต้องแก้ก่อนทำอย่างอื่น

หน้า /blog/ ลิงก์เสีย 7 ลิงก์

ลิงก์ไปบทความร่าง /blog/…/ ซึ่งไม่ได้ส่งออกไป WordPress เปิดแล้วเจอ 404 (ลองบน WordPress ในเครื่องแล้ว)

/blog/ ใหม่ทำให้บทความเดิมไม่มีลิงก์เข้า

/blog/ บนเว็บจริงเป็น "Knowledge Hub" ที่ลิงก์ไปบทความเดิมทั้ง 12 เรื่องกับหมวดบทความ ส่วนของเราไม่มีลิงก์ไปบทความพวกนั้นเลย

เนื้อหาบางกว่าเว็บจริงครึ่งหนึ่ง

หน้าแรก /corporate/ /education/ /sport/ /event/ ของเรามีตัวหนังสือราว 50–60% ของเว็บจริง ซึ่ง v22 สั่งไว้ว่าต้องย้ายเนื้อหาเดิมที่มีผลกับ SEO มาด้วย

อัปเดต 22 ต.ค. (หลังเคาะ): ระยะ 0–1 เสร็จ · ระยะ 2–4 ทำส่วนที่ไม่ต้องรอแล้ว · รายการที่ยังรอ ดู PLAN.md หัวข้อ "ยังเหลือ (รอ)"

แก้แล้วในรอบนี้ (มีเทสกันพลาดเพิ่มอีก 3 ข้อ รวมเป็น 87/87): ข้อความ "[ยืนยันบริการ]" ในกล่องดูรูป · ข้อความ "ต้นแบบสำหรับคุยภายใน" ใน footer ทุกหน้า · ข้อความต้นแบบในฟอร์มติดต่อ · หน้านโยบาย/เงื่อนไขที่ยังเป็นร่าง ตั้งไม่ส่งออกแล้ว ให้เว็บจริงใช้หน้าเดิม · ปุ่ม LINE ชี้ @teamdee จริงทุกปุ่ม · ไม่มีคำว่าโรงงานบนเว็บจริงแล้ว

ระยะ 4

Staging จากสำเนาเว็บจริง

2–5 พ.ย.
  • สำเนาเว็บจริงขึ้น staging (noindex ทั้งเว็บ) แล้วติดธีมใหม่
  • ไล่ตรวจ 44 URL เดิม: ตอบ 200 ที่ URL เดิม · บทความ 12 เรื่อง หมวด 3 หมวด และหน้าเดิม (/calculations/ /collar-styles/ /production-techniques/ /services/ /pdpa/ /privacy-policy/ /terms-conditions/) แสดงถูกกับธีมใหม่ ทั้งที่ทำด้วย Elementor
  • /serviecs/ → /services/ และ /terms/ → /terms-conditions/ ยัง redirect · /test-page/ /thank-you/ ตั้ง noindex และเอาออกจาก Sitemap (ตรวจหน้า test ก่อนลบจริง)
  • แบนเนอร์คุกกี้ (Complianz) · canonical · sitemap · ไม่สร้าง redirect จากชื่อแผน v20/v21
  • เก็บรายงานก่อนย้าย: index, คลิก, 404 จาก Search Console
เสร็จเมื่อ: สคริปต์ตรวจ 44 URL บน staging ผ่านทั้งหมด · screenshot หน้าเดิมทุกหน้า
ต้องได้: สิทธิ์ WordPress / hosting / Search Console (เรื่องที่ 1) ภายใน 30 ต.ค.
