## ข้อที่เจอ (เรียงตามความหนัก)

### P0 — ต้องแก้ก่อนขึ้นจริง
1. **มือถือ: แถบติดต่อด่วน (โทร / LINE) ล่างจอมองไม่เห็น**
   - หลักฐาน: ที่ 390px `documentElement.scrollWidth = 640`, `innerWidth = 640`, `innerHeight = 1386` ทั้งที่จอจริง 390×844 → `.mobilebar` (fixed) ไปอยู่ที่ top 1322 นอกจอ
   - ต้นเหตุ: `li.hm-uses-row` (แถวกลุ่มลูกค้า) กว้าง 640 ไม่ถูกตัด เพราะเป็น grid item ที่ `min-width: auto` ยืดตามรางเลื่อนข้างใน (`src/styles/home.css:2056` + `:2071`) · `body{overflow-x:clip}` แค่ซ่อนภาพ แต่ Chrome มือถือยังขยาย layout viewport
   - แก้: `.hm-uses-rows > li { min-width: 0 }` (หรือ `grid-template-columns: minmax(0,1fr)`) แล้ววัด scrollWidth = 390 ซ้ำ
2. **cookie consent ยังปิดอยู่** (`site.json cookieConsent: false`) — ต้องเปิดคืนก่อน launch

### P1 — ควรแก้ก่อนขึ้นจริง
3. **สไลด์แบนเนอร์ hero เลื่อนเองไม่มีปุ่มหยุด** (WCAG 2.2.2) — มีแค่จุดเลือกสไลด์ · เสนอ: หยุดเมื่อ hover/focus + ปุ่ม pause เล็กข้างจุด หรือเลิกเลื่อนเอง
4. **มือถือ: ข้อความจุดขาย 8 ช่องชนกัน** — ช่องละ 88px ข้อความไทยตัดบรรทัดไม่ได้ ("เอกสารจัดซื้อครบ" ทับ "เคลมงานผลิตฟรี" ทับ "สั่งเพิ่มราคาเดิม") เห็นใน screenshot 390
5. **หัวข้อส้มบนพื้นครีม ต่ำกว่าเกณฑ์** — `#cta-quote-h .hm-hl` #f05a00 บน #f2f0ed = 2.99:1 (ตัวใหญ่ต้อง 3:1) · ขยับเป็น #e65200 หรือเข้มกว่าเล็กน้อยก็ผ่าน
6. **logo marquee เลื่อนตลอดไม่มีปุ่มหยุด** (`data-marquee-nobtn` — อาร์ตตัดสินไว้แล้ว) · ถ้าเคารพ `prefers-reduced-motion` อยู่แล้วถือว่ารับได้ แต่ WCAG 2.2.2 ยังนับเป็นข้อ

### P2 — แก้ได้ในรอบเก็บงาน
7. `.hm-help__no` #c24b00 บน #f3f1ee = 4.3:1 (ตัวเล็กต้อง 4.5:1) — เข้มขึ้นนิดเดียวพอ
8. หัวข้อข้ามระดับ: H2 ในส่วน #story → H4 ใน timeline (ไม่มี H3) — เปลี่ยน H4 เป็น H3 (ขนาดตัวคง CSS เดิม)
9. น้ำหนักรวมเมื่อเลื่อนจนสุด ≈ 10.9 MB (รูป 10.4 MB, 247 ไฟล์)
   - ไอคอน 3D 240px แสดงจริง 60–88px
   - รูปการ์ดรีวิว 800w แสดงจริง ~195px (`sizes` ยังกว้างเกิน)
   - iframe คลิป Facebook 3 ตัว — ควรโหลดเมื่อกดเล่น (facade) แทนโหลดทันที
10. `site-extras-*.css` 342 KB โหลดตั้งแต่ต้น — ถ้าแยกส่วนที่หน้าแรกไม่ใช้ได้จะเบาลงมาก
11. มี request ไป `secure.gravatar.com` (มาจาก WP admin bar ตอน login) — ผู้เข้าชมจริงไม่เห็น แต่ควรเช็คหลัง export ว่าไม่ติดไป

### P3 — ขัดเกลา
12. easing แบบเด้ง `cubic-bezier(.34,1.56,.64,1)` ที่ `.fcta__orb` (`src/styles/main.css:977`), `main.css:927`, `page-project.css:69-70` — เปลี่ยนเป็น ease-out (เช่น `cubic-bezier(.16,1,.3,1)` ที่ใช้อยู่แล้ว)
13. H3 "1ช่วยคิด" — screen reader อ่านเลขติดหัวข้อ · ให้เลขเป็น `aria-hidden` หรือมีช่องว่าง/จุด

## ตรวจแล้วผ่าน
- H1 = 1, ไม่มี id ซ้ำ, รูปพังไม่มี, รูปทุกรูปมี alt, `lang="th"`, ไม่มี console error, request ทั้งหมด 200
- ไม่มีคำต้องห้าม (โรงงาน), ไม่มี emoji
- Skip link + landmark ครบ · meta description, og:image, canonical, JSON-LD (LocalBusiness + FAQPage) ครบ
- กด Tab จริง: โฟกัสเห็นชัด (เส้นดำ 3px + วงขาว) · ปุ่ม LINE ลอยมีชื่อ "ทัก LINE ขอราคา…" จากข้อความข้างใน
- มือถือ: ปุ่มกดทุกปุ่ม ≥ 24px · ไม่มีตัวหนังสือเล็กกว่า 12px (ยกเว้นตัวใน SVG)
- โหลดแรก (ยังไม่เลื่อน) 25 ไฟล์ 833 KB, DOMContentLoaded ~0.9 วินาที — lazy-load ทำงานดี

## ข้อที่ตัดออก (false positive)
- detector บอก "ปุ่มไม่มีชื่อ" ที่ปุ่ม LINE ลอย → จริงๆ มีชื่อจากข้อความข้างใน
- detector บอก "โฟกัสมองไม่เห็น" 20 จุด → เกิดจากสคริปต์เรียก `focus()` ซึ่งไม่ทริก `:focus-visible` · กด Tab จริงแล้วเห็นชัด
- ปุ่ม CTA ใน hero ไม่มีชื่อ → เป็นสไลด์ที่ซ่อน (inert)

## ยังไม่ได้ตรวจ
- สีตัวหนังสือ hero ทับรูป (detector วัดได้ 2.6–2.7:1 ระหว่างสไลด์กำลังเปลี่ยน) — ต้องเทียบตอนสไลด์นิ่งทีละภาพ
- การสแกน detector ที่ 390 หมดเวลา · ซูม 200% · screen reader จริง (VoiceOver)
- คลิป FB ในหน้ารีวิว ต้องให้อาร์ตลองใน Chrome จริง

## อัปเดต 4 พ.ย. — แก้ P0 ข้อ 1 แล้ว (อาร์ต "แก้ 0")
